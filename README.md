# E-repetitor

Платформа для независимых репетиторов, учеников и родителей.

**Сайт проекта: [zaladdin.github.io/E-repetitor](https://zaladdin.github.io/E-repetitor/).**

Репетитор самостоятельно регистрируется, подключает учеников, ведёт расписание,
создаёт тесты и учитывает оплаты. У ученика один постоянный ID на всей платформе.
Родитель после подтверждения связи с ребёнком видит все его предметы,
преподавателей, опубликованные результаты и статусы оплаты в одном кабинете.

## Состояние проекта

Разработка начата по `E-Repetitor_Technical_Specification_v1.1_Final.docx`
(22 сентября 2026). Готов **локальный интерактивный прототип** на
Next.js, React и TypeScript: три кабинета, предметы, запросы подключения по ID,
подтверждение учеником, отзыв связи и общий обзор предметов для родителя.

**Готова основа серверных аккаунтов:** NestJS + PostgreSQL, регистрация
по email, подтверждение почты, вход, восстановление пароля, сессии, несколько
ролей и постоянный Student ID. Предметы преподавателя уже сохраняются через API.

Добавлены сохраняемые запросы по Student ID, подтверждение учеником,
состояния обучения и родительский обзор предметов у разных преподавателей.
Правила и сценарий описаны в [документе подключений](docs/CONNECTIONS.md).

Для новых учеников доступны [временные записи и приглашения по email](docs/INVITATIONS.md):
ученик сам активирует аккаунт и подтверждает обучение по одноразовой ссылке.

Добавлены [индивидуальные занятия](docs/LESSONS.md): расписание по неделям,
переносы, отмены, посещаемость и история. API предотвращает пересечения
преподавателя и скрывает его личные заметки от ученика и родителя.

Добавлены [тесты в личных кабинетах](docs/TESTS.md): конструктор трёх типов
вопросов, неизменяемые версии, назначения, попытки с сохранением ответов,
автопроверка, ручная оценка и публикация результатов для ученика и родителя.

Добавлен [ручной учёт оплаты](docs/PAYMENTS.md): преподаватель создаёт запись
за период, пакет или занятие и ставит галочку «Оплачено». Родитель и ученик видят
статус; деньги передаются вне платформы. Исправления сохраняются в истории.

Добавлен [общий обзор кабинета](docs/OVERVIEW.md): ближайшие занятия,
действия по тестам, опубликованные результаты, посещаемость и отметки оплаты.
Родитель выбирает ребёнка или смотрит всех детей; сводка объединяет преподавателей.

Добавлен [центр уведомлений](docs/NOTIFICATIONS.md): события занятий и тестов,
настройки каналов и очередь писем с повторными попытками через локальную почту.

Добавлен [базовый кабинет администратора](docs/ADMIN.md): статистика, поиск
пользователей, управление доступом с причиной и журнал действий.

Проведена [локальная подготовка пилота](docs/PILOT.md): сквозной сценарий двух
репетиторов, ученика и родителя, проверка доступа и восстановление копии базы.
[Инструкция резервного восстановления](docs/BACKUP-RESTORE.md).

`/` и `/account/` открывают реальные тестовые аккаунты. `/demo/` сохраняет прежние
вымышленные примеры в браузере. Подключения в аккаунтах используют серверный API.
Домашние задания отложены. Остатки пакетов и частичные оплаты ещё не реализованы.
Используйте вымышленные данные для локальных проверок.

## Запуск приложения

Node.js 22.13+ и npm. Для полного сценария нужны PostgreSQL и Mailpit.
Подробный порядок настройки: [Аккаунты и локальный сервер](docs/ACCOUNTS.md).

```sh
npm ci --ignore-scripts
npm --prefix api ci --ignore-scripts
# После настройки .env и api/.env по примерам:
npm run infra:up
npm run api:migrate
npm run api:build
# В отдельных терминалах:
npm run api:start
npm run dev
```

Интерфейс: `http://127.0.0.1:3000/`. Локальная почта: `http://127.0.0.1:8025/`.
На Windows команды можно вызывать через `npm.cmd`.
На исходном Windows-хосте подготовлен portable PostgreSQL, запускаемый через
`./scripts/start-local-infra.ps1`, вместо Docker. Данные находятся в `.local/`.

Без API можно посмотреть демо по `http://127.0.0.1:3000/demo/` после `npm run dev`.

```sh
npm run check          # frontend: lint, TypeScript, unit tests, build
npm run api:test       # integration tests: отдельная TEST_DATABASE_URL
npm run check:all      # обе части
```

Статическая сборка интерфейса создаётся в `out/`. Для публикации по вложенному
пути задайте `NEXT_PUBLIC_BASE_PATH` перед сборкой. API разворачивается отдельно;
GitHub Pages не может запустить PostgreSQL и NestJS.
`.github/workflows/ci.yml` проверяет обе части приложения; деплой в нём не настроен.

## Как проверить сценарий демо

1. Откройте `/demo/`, выберите «Мурад · преподаватель», нажмите «Подключить ученика».
   Укажите `STU-K7M4-P92X` и предмет «Физика».
2. Переключитесь на «Али · ученик», откройте «Запросы» и примите приглашение.
3. В кабинете «Лейла · родитель» у Али появятся и математика, и физика.
   У Анны в кабинете останется только её обучение.
4. Для проверки нового родителя выберите «Нигяр · родитель», добавьте
   `STU-B6N2-R85T`, затем подтвердите запрос в кабинете Софии.
   До подтверждения сведения о ребёнке недоступны через представление родителя.
5. Перезагрузите страницу — связи сохраняются. «Сбросить демо» возвращает примеры.

У Анны есть две роли — преподаватель и родитель. Других родителей и нескольких
детей можно подключать такими же запросами. Эти демонстрационные связи не связаны с серверными аккаунтами.

## Структура

- `src/app` — Next.js страницы, общие стили и метаданные.
- `src/components` — оболочка кабинетов, формы и представления трёх ролей.
- `src/domain` — отдельная модель связей, команды, проекции, проверки и тесты.
- `src/lib` — HTTP-клиент аккаунтов и хранение демонстрации в браузере.
- `api/` — NestJS API, SQL-миграции, интеграционные тесты PostgreSQL.
- `compose.yml` — локальные PostgreSQL и Mailpit.
- `docs/design` — концепт первого экрана и система оформления.

Доменный модуль описывает правила связей для демо. Серверные аккаунты,
подключения и разграничение доступа проверяются отдельными API-тестами.

## GitHub Pages

Сайт публикуется из папки `docs` ветки `main` средствами GitHub Pages и Jekyll.
Главная страница — `docs/index.md`, настройки — `docs/_config.yml`.
После отправки изменений в `main` GitHub автоматически пересобирает сайт.
На опубликованном сайте доступны концепция и требования. Локальное приложение
запускается отдельно; текущая настройка Pages не собирает Next.js автоматически.

## Подтверждённые требования

- Самостоятельная регистрация независимых преподавателей.
- Кабинеты преподавателя, ученика и родителя с разграничением доступа.
- Разные направления обучения и собственные материалы преподавателей.
- Создание тестов через конструктор вопросов внутри системы.
- Единый профиль и постоянный ID ученика для всех преподавателей.
- Общий родительский обзор предметов, результатов и оплаты ребёнка.

При расхождении первоначальных предложений с ТЗ приоритет имеют уточнения
v1.1 (§21–26). По решению пользователя домашние задания пока отложены.
Ручные отметки оплаты реализованы. Расширенный учёт пакетов (количество занятий,
остаток, частичные суммы) остаётся отдельной задачей. Следующий этап — тестовое
размещение с HTTPS и почтой, затем закрытый пилот с участниками.

## Навыки разработки

В `.agents/skills/` сохранены `frontend-design`, `ui-ux-pro-max` и
`web-design-guidelines`. Их исходники и точные commit SHA указаны в
[описании установки](docs/skills.md). Лицензии, поставляемые с исходниками,
сохранены рядом с соответствующими навыками.

Ссылки на `C:/Users/Zaladdin/...` и `E:/E-repetitor/...` в инструкциях относятся
к исходной рабочей среде Windows. На другом компьютере необходимо сопоставить
эти пути с расположением проекта и инструментов Codex.
