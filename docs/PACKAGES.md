# Пакеты занятий

Преподаватель создаёт пакет для конкретного ученика и предмета, указывает число
занятий и общую стоимость. Ученик и подтверждённый родитель видят остаток,
статус оплаты и историю занятий. Деньги передаются вне платформы.

## Как пользоваться

1. В кабинете откройте «Пакеты занятий» и создайте пакет для активного обучения.
   Число занятий — от 1 до 1000. Стоимость обязательна, валюта выбирается явно.
2. Пакет автоматически появляется одной записью в «Учёте оплаты». После
   получения денег преподаватель ставит там галочку «Оплачено».
3. После окончания урока сначала отметьте посещаемость в расписании.
4. В пакете выберите списание, затем конкретное занятие и подтвердите действие.
   Для пропуска нужна причина. Посещаемость сама по себе не уменьшает остаток.
5. В истории можно вернуть ошибочное списание с причиной. Исходная операция
   сохраняется; возвращённое занятие снова доступно для правильного списания.
6. Закрытие прекращает новые списания. Неиспользованный остаток и вся история
   остаются видимыми. Закрытие не меняет галочку оплаты и не возвращает деньги.

Платформа допускает явное списание из неоплаченного пакета: преподаватель может
проводить занятия в долг. Статус оплаты и остаток занятий — разные показатели.
У обычной записи оплаты с названием «Пакет» остаток не появляется автоматически:
для количественного учёта создайте пакет в соответствующем разделе.

## Правила учёта

- Начальная операция добавляет количество занятий; каждое списание уменьшает
  остаток на одно, возврат добавляет одно. Отрицательный остаток запрещён.
- Списываются только закончившиеся занятия этого же обучения со статусом
  «Проведено» или «Ученик отсутствовал». Отменённые, будущие и перенесённые
  исходные занятия недоступны.
- Одно занятие не может иметь два действующих списания, в том числе в разных
  пакетах. Повтор запроса с тем же ключом не создаёт вторую операцию.
- Ошибочное списание исправляется возвратом, без удаления истории. После
  закрытия пакета или отмены его записи оплаты возврат по-прежнему разрешён.
- Отмена записи оплаты запрещает новые списания из связанного пакета.
- Версии пакета и занятия защищают от одновременных изменений. При конфликте
  обновите данные и проверьте действие перед повтором.
- Если после списания исправлена посещаемость, преподаватель отдельно проверяет
  необходимость возврата; изменение посещаемости не переписывает историю пакета.

## Доступ и хранение

При обновлении существующей локальной установки сначала сохраните копию базы,
затем выполните `npm run api:migrate` и `npm run local`. Миграции не запускаются
автоматически командой `local`. Для повторного старта готовой сборки используйте
`npm run local:start`; без пересборки изменения интерфейса не появятся.

Преподаватель управляет только своими пакетами. Ученик читает пакеты своего
подтверждённого обучения. Родителю нужны активные связь с ребёнком, обучение и
аккаунт ученика; отзыв связи прекращает доступ на сервере.

Семья видит движения количества и связанные занятия. Причины исправлений,
личные заметки и технические данные запросов семье не передаются.

Миграция `010_lesson_packages.sql` добавляет пакеты и журнал операций, сохраняя
существующий журнал оплаты единственным источником галочки. Создание пакета,
запись оплаты и начальный остаток сохраняются одной транзакцией. Старые
миграции не изменены. При откате кода таблицы и историю следует сохранить;
удаление данных не входит в процедуру отката.

## Границы этой версии

Реализована часть §24: количество, цена, остаток, привязка списания к Lesson и
компенсирующие исправления. Частичные суммы оплаты, сроки действия пакетов,
автоматическое списание и произвольное изменение количества остаются будущими
расширениями. Домашние задания и публичное размещение отложены.

Фактические проверки и ограничения: [отчёт двух этапов](PACKAGES-VERIFICATION.html).
