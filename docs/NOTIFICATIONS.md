# Уведомления — первая версия

Добавлен общий центр уведомлений для всех ролей аккаунта. Он показывает новые
события, количество непрочитанных, фильтр и постраничную историю. Можно отметить
событие прочитанным или перейти в расписание/тесты нужной роли.

| Событие | Получатели |
| --- | --- |
| Напоминание в течение часа перед занятием | Преподаватель, ученик, подтверждённые родители |
| Перенос или отмена занятия | Ученик и подтверждённые родители |
| Назначение теста | Ученик |
| Публикация результата | Ученик и подтверждённые родители |

Для каждого типа независимо настраиваются кабинет и email. По умолчанию кабинет
включён, письма выключены. Настройки общие для ролей. Изменения применяются к новым
событиям; выключение email также отменяет ещё не отправленную очередь этого типа.
Старые события кабинета сохраняются, пока пользователь имеет доступ к данным.
Конфликт версий настроек возвращает 409 и сохраняет черновик в интерфейсе.

## Доступ и содержание

Каждое чтение и отправка проверяют текущего владельца и связь с обучением.
Родителю требуются активные обучение, аккаунт ребёнка и первоначальная одобренная
связь. Отзыв и повторное подключение не возвращают старые уведомления.
Родитель не получает уведомление о назначении теста или неопубликованные итоги.
В центре нет вопросов, ответов, баллов и личных заметок преподавателя.
Письмо содержит только общее сообщение и ссылку на кабинет без данных ребёнка.

## Сервер и очередь

Миграция `008_notifications.sql` добавляет настройки, события и устойчивую очередь
PostgreSQL. Изменение занятия, назначение и публикация записывают событие в той же
транзакции. Уникальный ключ получателя/роли/типа/события предотвращает дублирование.
SQL внешние ключи связывают уведомление с правильным обучением, занятием и попыткой.

Работник включается явно: `NOTIFICATION_WORKER_ENABLED=true` в `api/.env` с
перезапуском API. По умолчанию выключен, в тестовой среде всегда выключен.
На локальном хосте включён только с PostgreSQL и Mailpit на loopback; реальная
отправка через внешний SMTP не настроена. Новые пакеты и сервисы не добавлены.

Проверка очереди — каждые 30 секунд, до 200 занятий и 20 отправок за проход,
без одновременных проходов одного процесса. Несколько работников используют
advisory lock для напоминаний и `FOR UPDATE SKIP LOCKED` для короткого захвата письма.
Аренда — 2 минуты; максимум 5 попыток, задержки повторов 60/120/240/480 секунд.
Состояния: `queued`, `sent`, `failed`, `cancelled`; число попыток и безопасная
категория ошибки сохраняются. После пяти неудач автоматические повторы прекращаются.

SMTP работает вне транзакции БД. Перед отправкой повторно проверяются права,
настройки и актуальность напоминания. Отзыв после этой проверки не может отозвать
уже отправляемое письмо, поэтому его текст не содержит учебных данных. При сбое
процесса после принятия письма SMTP, но до записи `sent`, возможна повторная
доставка. Message-ID стабилен, однако гарантия exactly-once не заявляется.
Если API выключен на протяжении всего часа перед занятием, напоминание пропускается;
просроченные напоминания не рассылаются после старта занятия.

## API

Все маршруты под `/api/v1`, с сессией и `X-Account-ID`. Изменения требуют
`Origin` и `X-Requested-With: ERepetitor`.

| Метод | Маршрут | Данные |
| --- | --- | --- |
| GET | `/notifications?limit=20&offset=0&unreadOnly=false` | `items,total,unreadTotal,limit,offset` |
| POST | `/notifications/:id/read` | `{}` → `id,readAt`, повтор безопасен |
| GET | `/notification-preferences` | `items:[type,inApp,email,version]` |
| PATCH | `/notification-preferences/:type` | `inApp,email,version`, конфликт → 409 |

Лимит 1–100, смещение 0–10000. Общий счётчик непрочитанных не зависит от страницы.
Интерфейс обновляет список при действиях, возвращении фокуса и раз в минуту на
видимой вкладке. При обновлении сохраняются открытые формы и загруженная глубина
истории. Ошибка обновления убирает устаревшее содержимое уведомлений.

## Границы этапа и следующий шаг

Домашние задания отложены по решению пользователя; уведомления о них появятся
вместе с модулем. Остатки пакетов и связанные напоминания также ещё не реализованы.
Сообщения о запросах подключения, сдаче теста и посещаемости остаются расширением.
Email о регистрации/восстановлении и приглашения сохраняют прежний механизм.

Следующий этап — **базовый кабинет администратора**. После него — подготовка
к пилоту: сквозные сценарии, проверка доступа и восстановление резервной копии.
Публикация API и настройка внешней почты требуют отдельного этапа развёртывания.
Откат приложения сохраняет таблицы и историю; применённую миграцию не изменять.
