# Проверка ручного учёта оплаты — 22 сентября 2026

Объём: записи преподавателя, галочка полной оплаты, исправления с причиной,
история и семейные представления. Деньги передаются вне платформы. Результат
находится в локальном приложении; публикация и production-деплой в этап не входят.

## Автоматические проверки

- `npm run check` прошёл: общий ESLint, TypeScript, **73 клиентских теста**
  в 11 файлах и production build `/`, `/account/`, `/demo/`.
- Профильный HTTP/PostgreSQL-набор ручной оплаты: **15/15** тестов без пропусков.
- Полный `npm run api:test`: **88/88** тестов в 6 наборах: 14 аккаунтов,
  11 подключений, 12 приглашений, 17 занятий, 19 тестирования и 15 ручной оплаты.
  Вместе с клиентом — **161 тест**; повторные прогоны не прибавляются к этому числу.
- После финальной правки сортировки журнала повторно прошли API build,
  профильный ESLint и все **15/15** тестов ручной оплаты, включая порядок первой страницы.
- Миграция `007_manual_payments.sql` применена к тестовой и локальной рабочей
  PostgreSQL. Предыдущие миграции прошли проверку контрольных сумм. API перезапущен.
- Локальный HTTP: `/account/` — 200, API health — `ok`, OpenAPI содержит все
  четыре пути журнала; анонимный запрос записей отклоняется с 401.
- Новые проверки сначала воспроизвели отсутствие API-маршрута и клиентского
  контракта, затем прошли после реализации.
- Процент покрытия не измерялся.

## Проверенные сценарии

- Запись создаётся только владельцем активного подтверждённого обучения;
  новая запись неоплаченная. Пара «сумма + валюта» необязательна, одиночное поле
  отклоняется. Неправильные UUID, `null`, строки вместо чисел, дробные минимальные
  единицы, неверные границы, лишние поля и подмена владельцев не проходят валидацию.
- Decimal-ввод клиента с запятой/точкой переводится точно в целое число минимальных
  единиц. Проверены 0,29, одна/две десятичные цифры, верхняя граница и отказ
  от округления лишних знаков, нуля, отрицательной суммы и экспоненциальной записи.
- Разные преподаватели изолированы. Чужие UUID и дополнительные роли аккаунта
  не открывают историю и право изменять запись. Семейные ответы не содержат
  email, внутренних причин или подробной истории.
- Ученик и подтверждённый родитель объединяют предметы разных преподавателей.
  Отзыв родительской связи и закрытие обучения убирают соответствующие записи
  из родительского представления; ученическая история сохраняется.
  Отдельно проверен активный Enrollment с существующей записью: при блокировке
  аккаунта ребёнка родительский доступ исчезает, а запись сохраняется у преподавателя.
- Отклоняются CSRF, устаревший `X-Account-ID`, недействительные/отозванные сессии.
  Реальный конкурентный тест отзывает сессию после HTTP guard, пока операция ждёт
  блокировку пользователя: изменение не происходит, история не пополняется.
- Конкурентное создание с одинаковым ключом даёт одну запись и одно событие.
  Повтор нормализованного запроса после изменения статуса возвращает текущую
  первоначальную запись; иной запрос с прежним ключом отклоняется.
- Статус задаётся целевым boolean и защищён версией. Повтор с актуальными
  версией/состоянием не создаёт события. Устаревшая версия отклоняется даже при
  совпадении целевого статуса. При конкурентной оплате/отмене один победитель.
- Снятие галочки требует причины и сохраняет предыдущее время отметки в истории.
  Аннулирование допускается только для неоплаченной записи. Аннулированная запись
  недоступна для дальнейших отметок; история остаётся. Удаления через API нет.
- Исправление старых записей доступно преподавателю после завершения обучения,
  новые записи при этом запрещены. Сумма/назначение существующей записи не меняются.
- Фильтры и пагинация ограничены и учитывают доступ. Оплаченные/неоплаченные
  выборки исключают аннулированные записи. История возвращает явные поля событий.
- PostgreSQL отклоняет неверную принадлежность Enrollment, несовместимые
  сумму/валюту и paid/timestamp, оплату аннулированной записи и неверное событие
  с пустым предыдущим статусом. Искусственная ошибка общего аудита откатывает
  одновременно изменение статуса и его подробную историю.
- OpenAPI содержит маршруты и типизированные схемы; клиент сохраняет версию,
  причину и желаемый статус при повторе после обновления сессии.

## Независимый обзор и оставшиеся проверки

Backend и frontend проверены другим участником по инструкциям ECC database,
security, React, TypeScript и code-review. Исправлено ограничение PostgreSQL:
`CHECK` с nullable boolean мог принять некорректное событие с результатом NULL;
добавлены явное ограничение и прямая регрессия БД. Миграция тогда ещё не применялась.

После добавления записи фильтр оплаченных/отменённых переключается на неоплаченные.
Новые записи выводятся первыми, чтобы результат не скрывался на последней странице.
История сохраняет хронологический порядок. Открытых замечаний обзора нет.

CUA вернул пустой список браузеров. Клики, клавиатурная навигация, восстановление
фокуса и мобильный вид **не проверены**. Сборка и HTTP-тесты их не заменяют.
При доступном браузере пройти [сценарий](PAYMENTS.html): создание с суммой и без,
галочка, снятие с причиной, отмена, фильтры, история, два преподавателя/родитель,
две вкладки, сетевой повтор и возврат в окно с незаполненной формой.

Частичные оплаты, количественный остаток пакета, списания по посещаемости и
платёжные интеграции не реализованы на этом этапе. Используются вымышленные данные.
