# Единый локальный запуск

Сайт и API работают одним процессом по адресу **http://127.0.0.1:3100/**.
Запросы интерфейса идут на `/api/v1` того же адреса, а ссылки в новых письмах
ведут обратно в этот кабинет. Данные сохраняются в существующей локальной
PostgreSQL. Нужен Node.js 22.13+.

## На уже настроенном компьютере

1. PostgreSQL и Mailpit должны работать. На исходном Windows-компьютере их можно
   запустить командой `./scripts/start-local-infra.ps1`; она использует готовую
   папку `.local/` и ничего не скачивает. Если окружение настроено через Docker,
   используйте `npm run infra:up`.
2. Из корня проекта выполните:

   ```powershell
   npm run local
   ```

3. После сообщения сервера откройте [приложение](http://127.0.0.1:3100/).
   Письма регистрации, приглашения и восстановления доступны в
   [Mailpit](http://127.0.0.1:8025/). Используйте адреса `@example.test` для проверки.
4. Остановите приложение через **Ctrl+C** в его терминале. PostgreSQL, Mailpit и
   ранее запущенные серверы остаются работать; их данные сохраняются.

Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd run local`.

Команда сначала проверяет локальные адреса базы и SMTP, доступность их портов и
свободный порт 3100, затем собирает интерфейс и API и запускает приложение.
Проверка порта базы не проверяет пароль и схему: при ошибке старта проверьте
`api/.env` и выполненные ранее миграции. Пароли команда не выводит.

## Первая настройка новой копии

Следуйте разделу «Локальный запуск через Docker» в [инструкции аккаунтов](ACCOUNTS.html):
подготовьте `.env`, `api/.env`, зависимости, инфраструктуру и выполните миграции.
После этого вместо двух отдельных команд сервера и интерфейса используйте
`npm run local`. Скрипт не устанавливает зависимости, не создаёт базы и не применяет
миграции автоматически. Нет обращения к облачному хостингу или внешнему SMTP.

## Сборка и повторный запуск

| Команда | Что делает |
| --- | --- |
| `npm run local` | Проверяет инфраструктуру, собирает и запускает приложение |
| `npm run local:build` | Собирает интерфейс и API; запущенная база для этого не нужна |
| `npm run local:start` | Запускает уже готовую локальную сборку |
| `npm run local:test` | Проверяет ограничения локального запуска и распознавание сборки |

Автоматического обновления при изменении исходников здесь нет: остановите процесс
и снова выполните `npm run local`. Для обычной разработки сохраняются
`npm run dev` и `npm run api:start` с прежними портами 3000 и 4000.
В браузере используйте `127.0.0.1`, чтобы Origin и cookies совпадали. Сессии cookies
привязаны к хосту, поэтому вход и выход на разных локальных портах могут влиять на
одну и ту же сессию.

## Настройки и ограничения

- Настройки базы и почты читаются из `api/.env`; переменные текущего терминала
  имеют приоритет. `DATABASE_URL` и `SMTP_HOST` должны указывать только на
  `127.0.0.1`, `localhost` или `::1`. URL базы не принимает query-параметры.
- Для процесса приложения принудительно задаются `NODE_ENV=development`,
  `HOST=127.0.0.1`, `PORT=3100`, `WEB_ORIGIN=http://127.0.0.1:3100`, `SERVE_WEB=true`.
  Файл `api/.env` не изменяется. Почтовые ссылки, созданные раньше, сохраняют
  прежний адрес; для нового адреса запросите новое письмо.
- Интерфейс собирается с `NEXT_PUBLIC_API_URL=/api/v1` и пустым `basePath` в
  `.local/web/`. Это отдельный статический экспорт; API собирается в `api/dist/`.
  Служебный маркер распознаёт локальную сборку и изменения её основных страниц.
- Сборка Next.js использует `NODE_ENV=production` для оптимизации файлов;
  запущенное приложение остаётся локальным development-окружением с HTTP.
- Напоминания и очередь писем работают, если `NOTIFICATION_WORKER_ENABLED=true`
  в настройках API. Команда сохраняет это явное решение пользователя.
- Скрипт не останавливает процесс, уже занявший порт 3100. Завершите предыдущий
  запуск в его терминале и повторите команду.

Этот режим проверяет приложение под единым адресом локально. Публичное размещение,
HTTPS и почта внешним получателям на этом этапе не настраиваются.

Фактические результаты: [проверка единого запуска](LOCAL-RUN-VERIFICATION.html).
