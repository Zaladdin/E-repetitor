# Подключения через Student ID

Эта часть проекта переносит Enrollment и ParentConnection из демонстрации
в аккаунты с хранением в PostgreSQL. Для запуска используются те же API,
база и Mailpit, что описаны в [инструкции аккаунтов](ACCOUNTS.html).
После обновления кода нужно выполнить `npm run api:migrate`, собрать и
перезапустить API. Данные из `/demo/` автоматически не переносятся.

## Рабочий сценарий

1. Ученик регистрируется, подтверждает почту и получает постоянный Student ID.
2. Преподаватель создаёт предмет и отправляет запрос по этому ID.
3. Ученик принимает или отклоняет запрос в своём кабинете. До принятия
   преподавателю доступны только ID, предмет и состояние запроса.
4. Второй преподаватель повторяет эти действия для другого предмета.
5. Родитель регистрируется и запрашивает связь по тому же ID. Ученик подтверждает её.
6. В родительском кабинете появляются ребёнок и его активные предметы у обоих
   преподавателей. Каждый преподаватель видит только собственные подключения.
7. Ученик или родитель может отозвать семейную связь. После этого обзор закрывается;
   повторное подключение требует нового запроса и подтверждения.

Для проверки используйте отдельные вымышленные аккаунты и локальную почту.
Кнопка обновления списков получает актуальное состояние с сервера; автоматические
уведомления и обновления в реальном времени относятся к следующему этапу.

## Состояния и повторные запросы

| Связь | Переход | Кто выполняет |
| --- | --- | --- |
| Enrollment | pending → active / rejected | Этот ученик |
| Enrollment | pending → expired | Сервер по времени PostgreSQL |
| Enrollment | active ↔ paused | Владелец предмета |
| Enrollment | active / paused → completed / cancelled | Владелец предмета |
| ParentConnection | pending → active / rejected | Этот ученик |
| ParentConnection | active → revoked | Этот ученик или связанный родитель |

Enrollment-запрос действует 7 дней — временное значение локального этапа.
Повтор ожидающего запроса возвращает ту же запись и не продлевает срок.
После истечения можно создать новый запрос. Активные связи не дублируются.
Отклонённая, завершённая или отозванная запись сохраняется в истории; новая
связь создаётся отдельно. У родительского запроса TTL пока не задан.

Список сразу показывает просроченный запрос как `expired`. Само изменение
в базе и запись аудита сохраняются при следующей операции с Enrollment этого
ученика; отдельный периодический обработчик пока не запущен. Подтвердить
просроченный запрос нельзя независимо от того, был ли уже сохранён `expired`.

## Границы доступа

- Student ID идентифицирует ученика, но не служит паролем или разрешением на просмотр.
- Роль и участник операции определяются сессией. Подстановка чужого ID связи
  или предмета не даёт права прочитать её или изменить состояние.
- Родительский обзор включает только активные семейные связи и активные предметы.
  Приостановленные или завершённые Enrollment в него не входят.
- Имя ученика скрыто от родителя до подтверждения и после отзыва связи. У преподавателя
  оно доступно по подтверждённым связям, включая сохранённую историю обучения.
- Email, другие родители, чужие преподавательские записи и приватные заметки
  не включены в родительское представление.
- Запросы ограничиваются по частоте; одинаковые незавершённые связи защищены
  ограничениями базы. Изменения состояний записываются в аудит.

Расписание и посещаемость описаны в [модуле занятий](LESSONS.html).
Результаты тестов и суммы оплат ещё не реализованы и не подменяются
в этих кабинетах демонстрационными значениями. Временные записи и одноразовые
приглашения описаны [отдельно](INVITATIONS.html). Вход ученика без email ещё не реализован.

API-контракт находится в `api/README.md` и в локальном OpenAPI
`http://127.0.0.1:4000/api/v1/openapi.json`. Автоматические проверки запускаются
через `npm run check` и `npm run api:test` с отдельной `TEST_DATABASE_URL`.

Фактические результаты: [проверка подключений](CONNECTIONS-VERIFICATION.html).
