## Реальная локальная проверка

API перезапущен с миграцией 008 и включённым работником после проверки, что БД
и SMTP находятся на loopback, SMTP — Mailpit. Health `ok`; OpenAPI содержит четыре
маршрута уведомлений/настроек. Существующие аккаунты и данные не удалялись.

Для отдельного QA-аккаунта с ролями преподавателя и родителя созданы вымышленные
ученик и связи. Создание, перенос и отмена занятий выполнены через рабочий API.
Фоновый работник создал два напоминания по ролям. В очереди две доставки `sent`,
по одной попытке; Mailpit содержит два соответствующих письма со ссылкой на кабинет,
без имени ребёнка, предмета и результатов.

Встроенный браузер Codex проверил:

1. Вход QA-аккаунта и ленту четырёх событий разных ролей.
2. Отметку прочтения: счётчик 4 → 3; фильтр показывает 3 непрочитанных.
3. Сохранность введённого, но не сохранённого названия предмета при обновлении ленты.
4. Включение email для публикации результата и сообщение об успешном сохранении.
5. Переход из родительского уведомления к роли «Родитель» с фокусом на расписании.
6. Узкий экран: снимок интерфейса, фактические `clientWidth=341`, `scrollWidth=341`;
   горизонтальной прокрутки нет. Временное ограничение размера затем снято.
7. Возврат к полной истории клавишей Space; после перезагрузки прочитанный статус
   и включённый флажок email сохранились. Проверенные console error/warn пусты.

Один клик сразу после изменения viewport не переключил checkbox; состояние
проверено, переключение с клавиатуры успешно. Один DOM-запрос свойства checkbox
истёк по времени; последующий accessibility snapshot подтвердил сохранённый флажок.
Эти ограничения браузерного инструмента не подменялись утверждением об успехе.

## Обзор и ограничения

Независимый обзор frontend по ECC React/TypeScript/code-review выявил и помог
исправить пропуск уровня заголовка и потерю загруженной истории при фоновом опросе.
Для второго исправления добавлена регрессия. Backend, схема БД, доступ и очередь
проверены отдельно от их реализации. Блокирующих замечаний не осталось.

После полного API-набора изменён только общий текст письма для случая, когда
email включён, а уведомления в кабинете выключены; финальная API-сборка прошла.
Нет внешней SMTP-проверки, нагрузочного теста, production-развёртывания, полного
аудита WCAG или гарантии exactly-once. Повтор после принятия SMTP и сбоя фиксации
возможен; детальные границы описаны в [правилах уведомлений](NOTIFICATIONS.html).

Изменения остаются локальными; commit, push и деплой не выполнялись.
