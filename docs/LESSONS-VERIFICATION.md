# Проверка занятий — 22 сентября 2026

Объём: индивидуальное расписание, переносы, отмены, посещаемость и история.
Результат находится в локальном приложении; публикация и production-деплой
в этот этап не входят.

## Автоматические проверки

- `npm run check`: ESLint, TypeScript, **56 тестов** клиента/дат/ссылок/демо,
  production build страниц `/`, `/account/`, `/demo/`.
- Полный API-набор: **54/54 HTTP/PostgreSQL integration-теста**, без пропусков:
  14 аккаунтов, 11 подключений, 12 приглашений, 17 занятий.
- После исправления валидации смещения часового пояса повторно выполнены
  API TypeScript build и все **17/17 тестов занятий**. Профильный ESLint прошёл.
- Всего **110 тестов**. Процент покрытия не измерялся.
- Новые клиентские тесты сначала воспроизвели отсутствие методов и помощников
  календаря, затем прошли после реализации. Отдельно добавлены проверки переходов
  летнего времени и недель, длина которых отличается от 168 часов.
- Миграция 005 применена к тестовой и локальной рабочей PostgreSQL 18.6.
  Миграции 001–004 не изменялись; API перезапущен с актуальной сборкой.
- Локальный HTTP: `/account/` отвечает 200, API health — `ok`, OpenAPI содержит
  все маршруты расписания, переноса, отмены, посещаемости и истории.

## Проверенные сценарии

- Преподаватели изолированы; известный чужой UUID, дополнительные роли аккаунта
  и подмена контекста не открывают доступ. Несовпадение `X-Account-ID` отклоняется.
- Ученик и подтверждённый родитель видят разных преподавателей; pending/revoked
  родитель не получает занятия. Приватные заметки и комментарии отсутствуют в
  семейных ответах; подробная история доступна только владельцу-преподавателю.
- Пересекающиеся конкурентные бронирования одного преподавателя имеют одного
  победителя. Проверен также параллельный перенос и создание для разных учеников.
  Соседние интервалы и разные преподаватели разрешены.
- Повтор создания с тем же ключом не создаёт второй урок или событие; изменённый
  запрос с прежним ключом отклоняется. Клиент сохраняет ключ при refresh/retry.
- Перенос сохраняет исходное время, новую запись и события обеих сторон.
  Конфликт времени откатывает перенос. Искусственная ошибка записи истории после
  создания замены также откатывает всю транзакцию, включая версию и новую запись.
- Посещаемость запрещена до окончания урока по часам БД; исправление требует
  причины и сохраняет предыдущие значения. Устаревшая версия не перезаписывает
  конкурентное изменение. Отменённые/перенесённые записи не меняются обычным действием.
- Отмена освобождает время и записывает attendance. Приостановка/закрытие обучения
  запрещает новые назначения, сохраняя возможность завершить ранее назначенное.
- Проверены пагинация, диапазоны, пересечение границы недели, строгие даты,
  смещения, длительность, HTTPS, поля разных форматов и отклонение лишних/null полей.
- Ограничения БД отклоняют неверного владельца, чужого ученика посещаемости,
  перенос в другой Enrollment, повторную замену и попытку включить списание.

## Независимый обзор и оставшаяся проверка

Применены ECC database/security/React/TypeScript/code-review инструкции.
Backend и frontend проверены другим участником разработки. Найдено и исправлено
одно замечание: JavaScript принимал смещения `+16:00`…`+23:59`, которые PostgreSQL
не поддерживает. Теперь они отклоняются как ошибка ввода; добавлены HTTP-регрессии
для создания и границ выборки. После повторного обзора открытых замечаний нет.

CUA вернул пустой список браузеров. Поэтому ручные клики, визуальная оценка,
клавиатурная навигация и мобильный вид новых экранов **не проверены**. Сборка и
HTTP-тесты не заменяют браузерную проверку. При её доступности нужно пройти
[сценарий занятий](LESSONS.html), проверить фокус диалогов/ошибок, смену роли и
недели, двойное нажатие сохранения, длинные заметки и узкий экран.

Финансовое списание и доставка уведомлений не реализованы. Группы, повторения
и редактор политики конфликтов отложены. После этого этапа пользователь попросил
пока пропустить домашние задания; следующий модуль по обновлённому плану — тесты.
