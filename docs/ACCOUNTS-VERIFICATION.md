# Проверка серверных аккаунтов — 22 сентября 2026

Объём: локальная серверная основа, регистрация по email, профили, сессии,
восстановление доступа, роли и собственные предметы. Проверки не означают
готовность всех функций ТЗ или production-развёртывания.

Это отчёт предыдущего этапа. Актуальные проверки подключений и общий состав тестов:
[проверка сохраняемых подключений](CONNECTIONS-VERIFICATION.html).

## Автоматические проверки

- `npm run check` прошёл: lint, TypeScript, 34 frontend/domain-теста, production
  build статических страниц `/`, `/account/`, `/demo/`. После очистки предупреждений
  в тестовом mock отдельно повторены lint, typecheck и тесты ссылок.
- NestJS API собирается TypeScript-компилятором.
- 14 integration-тестов прошли на PostgreSQL 18.6; пропущенных нет.
- Применены миграции `001_accounts.sql` и `002_subject_unicode.sql` к отдельным
  локальным БД разработки и тестирования.
- Проверены строгие DTO, CSRF, обязательное подтверждение почты, Argon2 и хранение
  только хешей токенов, ограничение запросов, отозванные/истёкшие сессии.
- Проверены повторное использование refresh, параллельное обновление, выход везде,
  одноразовый сброс пароля, недоступность предметов другого преподавателя,
  `X-Account-ID` против действий из устаревшей вкладки, rollback регистрации,
  одинаковый публичный ответ при сбое SMTP и OpenAPI.
- Проверка зависимостей `npm audit`: 0 известных уязвимостей в frontend и API
  на момент запуска. Это не доказательство отсутствия всех уязвимостей.

## Проверки в браузере

Codex In-app Browser, локальные API/PostgreSQL и настоящий SMTP-путь через Mailpit:

- Регистрация вымышленного преподавателя → письмо → подтверждение → вход.
- Создание «Математики» → перезагрузка → сохранённый предмет.
- Добавление роли ученика к тому же аккаунту → постоянный Student ID.
- Вторая вкладка использует тот же аккаунт; выход в первой убирает кабинет во второй.
- Вход во второй аккаунт обновляет обе вкладки; «Математика» первого преподавателя
  не попадает в список второго.
- Переход по ссылке подтверждения в уже открытой `/account/` показывает нужную форму
  без reload; после подтверждения секретного fragment нет в адресной строке.
- Фокус после перехода с входа на регистрацию находится на заголовке новой формы.
- DOM на ширине 429 px не имеет горизонтального переполнения страницы.

Суммарно 48 автоматических тестов: 34 frontend/domain и 14 API.

## Обзор и ограничения

Выполнены security/SQL, TypeScript и React-обзоры. Исправлены найденные проблемы:
обход throttling вариантами адреса, неправильные HTTP-коды ошибок тела,
различие ответов при сбое SMTP, устаревший аккаунт между вкладками, отсутствие
пагинации предметов и потеря клавиатурного фокуса.

Docker Compose описан и проверен чтением конфигурации; контейнеры на этом хосте
не запускались из-за ошибки Docker/отключённой WSL. Реальные БД и Mailpit запущены
из официальных portable-сборок, только на 127.0.0.1. CI подготовлен, но удалённый
GitHub Actions запуск не выполнялся в рамках этого этапа.

Проверки восстановления пароля, expiry, concurrency и изоляции выполнялись через
настоящий HTTP API и тестовую БД. Это не браузерные end-to-end тесты каждого случая.
Постоянная очередь email, backup/restore, production HTTPS/SMTP, финальные
юридические тексты и username-only recovery пока не реализованы.
