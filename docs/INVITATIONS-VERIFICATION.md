# Проверка приглашений — 22 сентября 2026

Объём: временные записи новых учеников, одноразовая активация, повторная
отправка и отзыв. Это локальный этап, без публикации или production-развёртывания.

## Автоматические проверки

- `npm run check` прошёл: ESLint, TypeScript, **41 тест** клиента/ссылок/демо,
  production build страниц `/`, `/account/`, `/demo/`.
- Сервер: **37 HTTP/PostgreSQL integration-тестов**, без пропусков или ошибок:
  14 аккаунтов, 11 подключений, 12 приглашений. API TypeScript build и профильный
  ESLint прошли.
- Всего **78 тестов**. Процент покрытия не измерялся.
- Четыре новые клиентские проверки сначала воспроизвели отсутствие нужных
  методов/разбора invitation fragment, затем прошли после реализации.
- Миграция 004 применена к отдельной тестовой и локальной рабочей БД PostgreSQL 18.6.
  Миграции 001–003 не изменялись. Локальный API перезапущен.

## Проверенные сценарии

- Только свой преподаватель и свой предмет; чужие UUID и роль родителя не дают доступа.
- Временная запись не создаёт аккаунт и Student ID до принятия.
- Принятие требует согласий и явного подтверждения обучения; создание аккаунта,
  StudentProfile, Enrollment и потребление токена атомарны.
- Существующий email не ведёт к объединению или изменению чужого аккаунта.
- Дубликаты, параллельное принятие, замена/отзыв токена и просроченные ссылки.
- Истечение во время записи Enrollment откатывает новые сущности и сохраняет аудит expiry.
- Токены хранятся в виде хешей; публичный preview не выдаёт имя/email ученика.
- Статусы SMTP, сбой доставки, ограничения по IP, преподавателю и общему получателю.
- Клиент привязывает приватные операции к текущему аккаунту, отбрасывает устаревший
  ответ, передаёт секрет в POST body и не обновляет сессию ради публичной активации.
- Invitation fragment удаляется из URL; новая ссылка в уже открытой странице
  заменяет прежнее действие без сохранения токена в адресной строке.

Отдельная локальная smoke-проверка использовала существующего вымышленного
QA-преподавателя: HTTP-вход → создание приглашения вымышленному `@example.test`
адресату → настоящий SMTP → `deliveryStatus:sent` → выход. Письмо находится
в Mailpit, в интернет оно не отправлялось. Токен не возвращался ответом создания.

## Обзор и границы

Независимый обзор применил ECC security/database/React/TypeScript/code-review guidance.
После исправлений незакрытых замечаний нет. Проверены порядок блокировок,
финальный контроль TTL, сохранение terminal states, согласия, привязка к аккаунту
и обработка устаревших ответов. В интерфейсе отзыв скрыт для expired, длинные
email переносятся внутри карточки.

В этой сессии CUA не предоставляет браузер: ручные клики, визуальная оценка новых
экранов и взаимодействие с клавиатуры не проверены. Прохождение React-сборки и
HTTP-тестов не заменяет эти проверки. Следующий браузерный проход должен выполнить
полный [сценарий приглашения](INVITATIONS.html), смену ссылки во время загрузки,
двойное нажатие отправки и проверку диалога отзыва на узком экране.

Очередь доставки после аварийной остановки, username без email, ссылки enrollment
и support-объединение не реализованы. GitHub/Pages и удалённый CI на этом этапе
не обновлялись. Результат подготовлен и проверен локально.
