# Проверка подключений — 22 сентября 2026

Объём: Enrollment и ParentConnection существующих аккаунтов, серверные права,
подтверждения, состояния обучения и родительский обзор. Временные профили,
приглашения, занятия, тесты и оплаты в эту проверку не входят.

Следующий этап и актуальное число проверок: [проверка приглашений](INVITATIONS-VERIFICATION.html).

## Результаты

- `npm run check` прошёл: lint, проверка типов, **37 тестов** клиента/демо и
  production build страниц `/`, `/account/`, `/demo/`.
- **25 HTTP/PostgreSQL integration-тестов** API прошли без пропусков: 14 тестов
  аккаунтов и 11 новых тестов связей. Использовалась отдельная тестовая БД PostgreSQL 18.6.
- Всего **62 автоматических теста**. Измерение процента покрытия не выполнялось.
- Добавлена миграция `003_connections.sql`; применена к тестовой и локальной
  рабочей БД. Миграции 001/002 сохранены без изменений.
- Локальный API перезапущен; `/api/v1/health` вернул `ok`, OpenAPI содержит
  девять путей нового модуля и PATCH для состояний Enrollment.

## Что проверяют тесты

- Два преподавателя подключают одного ученика; каждый видит свои связи,
  родитель после подтверждения видит оба активных предмета.
- До подтверждения учебные сведения и имя ученика не раскрываются;
  чужой ученик, родитель или преподаватель не может подтвердить связь.
- Подстановка чужого UUID предмета или связи не открывает доступ.
- Повторные и параллельные запросы не дублируют действующие связи и аудит.
- Просроченное подтверждение возвращает конфликт, сохраняет `expired`
  вместе с аудитом; повторное подключение создаёт новую запись.
- Пауза, возобновление, завершение и отмена соблюдают разрешённые переходы.
- Несколько родителей и детей, отзыв со стороны ученика/родителя и повторный запрос.
- Разделение рабочих ролей, строгие DTO, пагинация, составные FK и уникальность БД.
- Ограничение частоты запросов учитывает варианты адреса; GET списка не сокращает
  окно ограничения POST. Аккаунт определяется проверенной сессией.
- Преподаватель может закрыть существующее обучение неактивного ученика.
- Клиент сохраняет метод PATCH, тело и `X-Account-ID` при повторе после обновления сессии.

## Обзор и ограничения

Выполнен независимый обзор схемы/SQL и обзор React, TypeScript и общего качества
по ECC-инструкциям. Блокирующих замечаний после исправлений не осталось.
Исправлены проверка TTL непосредственно при UPDATE, управление связью неактивного
ученика, отдельное окно ограничения POST и устаревшие описания на экране входа.

Новые экраны не прошли ручной сценарий кликами: в текущей сессии Codex отсутствует
доступный браузерный провайдер. React-проверка основана на чтении кода, проверке
типов и сборке; client-тесты проверяют HTTP-контракт, а не работу DOM. Проверки
браузера предыдущего этапа описаны отдельно в [отчёте аккаунтов](ACCOUNTS-VERIFICATION.html).

Для следующей браузерной проверки: пройти сценарий из [описания подключений](CONNECTIONS.html),
сменить роль во время загрузки, отозвать доступ при загруженных нескольких страницах,
дважды нажать подтверждение и проверить клавиатурный фокус диалога.

Изменения подготовлены локально; удалённые CI, GitHub Pages и production не обновлялись
в рамках этого этапа. Docker на данном хосте по-прежнему не используется: проверки
выполнены с локальными portable PostgreSQL и Mailpit.
