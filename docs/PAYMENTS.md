# Ручной учёт оплаты

По уточнению пользователя деньги передаются вне платформы. Преподаватель
самостоятельно отмечает получение оплаты галочкой. Ученик и родитель видят
статус; банковских операций и кнопки оплаты в приложении нет.

## Сценарий преподавателя

1. В личном кабинете откройте «Учёт оплаты» и нажмите «Добавить запись».
2. Выберите ученика и предмет из активного подтверждённого обучения.
3. Укажите назначение, например «Математика за сентябрь», «Пакет из 8 занятий»
   или «Занятие 22 сентября». Назначение — свободный текст, видимый семье.
4. При необходимости укажите сумму и валюту. Без суммы можно вести только
   отметки. Валюта явно выбирается в форме; доступны AZN, RUB, USD и EUR.
5. Новая запись появляется как неоплаченная. После получения денег поставьте
   галочку «Оплачено». Приложение сохранит время отметки и автора изменения.
6. Если галочка поставлена ошибочно, снимите её и укажите причину. Запись снова
   станет неоплаченной, предыдущая отметка останется в истории.

Ошибочную неоплаченную запись можно отменить с причиной. Она останется в
журнале со статусом «Запись отменена» и будет недоступна для дальнейших изменений.
У оплаченной записи сначала исправляется отметка. Назначение и сумма созданной
записи неизменяемы: для исправления сохраните отмену и создайте новую запись.

Фильтры показывают все, оплаченные, неоплаченные или отменённые записи.
Отменённые не входят в выборку оплаченных/неоплаченных. Список и история имеют
постраничную загрузку; новые записи показываются первыми. Для одного обучения
можно создать несколько записей.

## Что видят ученик и родитель

Ученик видит записи по своим подтверждённым предметам, включая историю закрытого
обучения. Родитель получает записи детей по всем доступным активным предметам
разных преподавателей. Для этого нужны активные ParentConnection, Enrollment
и аккаунт ребёнка. Отзыв родительской связи или закрытие обучения прекращает
соответствующий родительский доступ — как в текущих занятиях и тестах.

Семье доступны назначение, сумма при наличии, валюта, статус и время отметки.
Причины исправлений и подробная история доступны только владельцу-преподавателю.
Сервер проверяет права на каждом запросе; публичный Student ID не даёт доступа.

## Правила первой версии

- Статусы — «Не оплачено» и «Оплачено»; отмена относится к самой записи.
  Галочка означает ручную отметку полной оплаты этой записи.
- `paidMarkedAt` — время установки галочки, а не подтверждённое банком время
  перевода. Снятие галочки сохраняет старое время в истории.
- Сумма необязательна. При заполнении: 0,01–9 999 999,99, до двух десятичных
  знаков. API и PostgreSQL хранят целое число минимальных единиц валюты;
  округления введённой суммы нет. Суммы разных валют не складываются.
- Создание требует активного обучения. Исправления ранее созданных записей
  остаются доступны преподавателю после приостановки или завершения обучения.
- Версия записи защищает от изменений в другой вкладке. Устаревший запрос
  отклоняется: обновите журнал перед повторным изменением.
- Создание с тем же ключом и содержимым возвращает прежнюю запись без дубля.
  Смена статуса передаёт желаемое значение, поэтому двойной клик не инвертирует
  его обратно. Все изменения и история фиксируются одной транзакцией.
- Причины снятия отметки/отмены обязательны, от 3 до 1000 символов. Назначение —
  до 200 символов. Удаления записей и истории через API нет.

## Границы этапа

Это первый ручной журнал. Период, пакет или отдельное занятие задаются названием
записи; отдельная связь с Lesson и календарные периоды пока не моделируются.
Название «Пакет из 8 занятий» само по себе не создаёт остаток занятий.

Расширенные требования §24 ТЗ — количество и остаток занятий, журнал списаний,
частичная оплата и корректировки сумм — сохранены для отдельного этапа. Сейчас
посещаемость не меняет оплату; автоматических списаний, долгов, уведомлений и
платёжных интеграций нет. Домашние задания остаются отложенными.

Модуль работает в серверных аккаунтах `/account/`, данные `/demo/` не меняются.
Запуск описан в [аккаунтах](ACCOUNTS.html), контракт — в `api/README.md`,
фактические проверки — в [отчёте](PAYMENTS-VERIFICATION.html).
