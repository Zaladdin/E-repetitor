# Подготовка пилота

Цель этапа — проверить совместную работу уже реализованных модулей и возможность
восстановить данные. Это локальный технический прогон на вымышленных данных;
публичный сервис ещё не развёрнут.

## Проверяемый сценарий

За основу взят §20.3 ТЗ v1.1 с изменениями пользователя: домашние задания отложены,
оплаты отмечает преподаватель вручную. Количественные пакеты и списания остаются
отдельной функцией и не входят в критерии этого прогона.

1. Преподаватель, ученик и родитель регистрируются и подтверждают email.
2. Два независимых преподавателя подключают одного ученика по постоянному Student ID
   к математике и физике; ученик подтверждает запросы.
3. Ученик подтверждает родителя, который видит оба предмета.
4. Преподаватель назначает занятие и отмечает посещаемость.
5. Преподаватель создаёт и назначает тест с выбором ответа и письменным вопросом.
   Ученик сдаёт работу; преподаватель проверяет и публикует результат.
6. Ученик и родитель видят опубликованные результаты, расписание и ручные статусы
   оплаты. Каждый преподаватель видит только своё обучение.
7. Отзыв родительской связи закрывает доступ к обзору, занятиям, оплатам и результатам.
   Собственные данные ученика и преподавателей сохраняются.
8. Резервная копия восстанавливается в новую базу, данные и схема сравниваются.

## Повторяемая проверка

```powershell
npm.cmd run check
npm.cmd run api:test
```

API-набор требует отдельную локальную `TEST_DATABASE_URL` с именем, заканчивающимся
на `_test`; он очищает только тестовые данные. Нельзя запускать его на рабочей базе.
Не запускайте несколько API-наборов параллельно в одной тестовой базе.
Сценарий пилота: `api/test/pilot.test.ts`.

Резервное восстановление выполняется отдельно по [инструкции](BACKUP-RESTORE.html).
Зафиксированные проверки, числа и ограничения: [отчёт этапа](PILOT-VERIFICATION.html).

## Что нужно для внешнего пилота

| Задача | Критерий готовности |
| --- | --- |
| Тестовое размещение | HTTPS-домен, frontend/API/PostgreSQL; GitHub Pages остаётся документацией и не запускает сервер |
| Почта | Подключён настоящий SMTP; подтверждение, восстановление и уведомления проверены на тестовых адресах |
| Согласия | Подготовлены Terms/Privacy и утверждены версии согласий вместо локальных тестовых текстов |
| Доступ оператора | Определён первый администратор и процедура выдачи/отзыва production-права |
| Резервные копии | Защищённое внешнее хранение, ежедневное расписание, сроки хранения и восстановление на staging |
| Нагрузка | Согласован размер пилота, измерены сценарии с соответствующим количеством данных и пользователей |
| Участники и обратная связь | Небольшая согласованная группа репетиторов/семей, канал ошибок и список проверочных заданий |

Следующий этап — подготовить тестовое размещение и повторить сценарий на нём,
затем провести закрытый пилот с участниками. Выбор провайдера, домена и внешних
сервисов требует конкретных исходных данных; этот локальный этап их не создаёт.
